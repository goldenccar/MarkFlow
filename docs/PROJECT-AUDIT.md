## 已处理的发现

| 问题 | 修复与验证 |
| --- | --- |
| 恢复副本直接写入会先截断已有目标，中途失败可能损坏旧副本 | 复用 `atomicWrite`，写好临时文件后替换；失败注入测试验证旧副本及临时文件清理 |
| 定位可把隐藏身份元数据的偏移传给只显示正文的 CodeMirror，产生 RangeError | `jump` 按正文长度限制；用真实 CodeMirror 状态验证越界与正常末尾位置 |
| 新生成窗口可能与自动保存、原生菜单动作交叉 | 取消待触发自动保存，关闭后恢复；统一忙碌/初始化检查；弹窗输入仍支持原生撤销重做 |
| 编译器只有 SDK/CLI，没有桌面可用入口 | 文件路径栏“生成”、标签加号和原生菜单均可进入；捕获未保存快照，错误定位，打开结果；7 组实际桌面验收通过 |
| 生成文档若在主进程加载编译依赖，会占用桌面事件线程 | 解析、测量、Office 打包移到独立 Worker；主进程仅授权与原子写入；轻量输出模块由 SDK 和桌面共用 |
| 编辑正文仍在界面线程整篇解析标题大纲 | 标题与 Mark 大纲一起交给后台 Worker；按文档标识和内容检查返回结果，过期大纲不能导航 |
| 未变化的大列表每次键入仍重复解析 | 只缓存精确列表原文的相对范围，限 32 项/约 2 MiB；身份与样式不缓存，测试覆盖文本变化及跨文档隔离 |
| Git 状态重复启动进程读取同一分支和远端 | 同一请求内复用读取结果，12 次降为 10 次；下一次仍读取真实配置，测试覆盖外部改动 |
| Mark 引用链被逐条递归重算，规模增大后耗时近二次增长 | 单次编译迭代展开并缓存引用；保留输出副本、样式和来源；测试覆盖 3,000 层、循环拒绝及计划摘要一致性 |
| 通用撤销历史每次变更重新序列化所有旧快照计算预算 | 累计维护旧快照字节数；保留分组、分支、撤销/重做、裁剪和至少一个检查点；4 项新回归通过 |
| 旧预览中转组件仅被测试使用 | 删除 `Preview.tsx`，渲染测试直接覆盖应用实际注册的文档模块；更新文档路径 |

新增面板、权限隔离与回归测试增加了总行数。本轮删掉了失去用途的中转层和重复执行，**不声称整个仓库净行数下降**。
