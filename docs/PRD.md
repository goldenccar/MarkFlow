# MarkFlow 产品需求文档

更新日期：2026-10-28（Asia/Shanghai）

MarkFlow 以本地文件为基础，提供写作、数学公式编辑和可选的 Git 版本记录，后续扩展文档、表格、演示与 PDF 处理。本 PRD 统一产品范围、模块命名、语言显示和验收要求，供设计与开发使用。

项目正式名称为 **MarkFlow**，OopsMD 为历史名称。程序名称、窗口标题及新安装包配置已统一为 MarkFlow；旧数据目录、安装升级标识和持久化键继续保留，以兼容已有设置、草稿与标签。历史记录和既有文件路径保留原名。

本次确定：文档使用 **Note**，表格使用 **Array**，演示使用 **Stage**，LaTeX 数学模块使用 **Formula**，取代 Geek。英文创建入口只显示英文名称；中文创建入口使用功能名称。PDF 只能打开已有文件进行阅读和修改，不能从零新建。

## 1 产品定位

用户在自己的本地文件夹中组织资料，通过同一个桌面工作区打开、编辑和保存不同类型的内容。首次创作可以先写后存；日常编辑不依赖账号或联网。需要版本记录和跨设备同步时，再明确启用 Git 和配置远端。

主要使用场景：

- 写 Markdown 内容、整理项目资料，并查看正文目录。
- 输入 LaTeX 数学片段，对照源码检查公式。
- 创建和编辑文档、工作簿与演示文件，后续分别由 Note、Array、Stage 提供。
- 打开已有 PDF，阅读或修改后保存。
- 在多个文件之间切换，保留各自的编辑状态、草稿和撤销历史。

## 2 当前实现与目标范围

| 能力 | 当前开发源码 | 产品目标或边界 |
| --- | --- | --- |
| Markdown | 已实现编辑、预览、源码、对照、Mark 局部排版与正文目录 | 继续作为现有文档类型维护 |
| Formula | 已有 LaTeX 数学片段编辑和 KaTeX 渲染，界面已由 Geek 改为 Formula | 功能范围保持数学片段编辑；中文入口本地化随语言机制实现 |
| Note | 尚未实现 Word 类文档编辑器 | 提供文档创建、编辑、排版与格式读写 |
| Array | 尚未实现电子表格编辑器、计算或图表 | 提供工作簿与单元格编辑；计算、图表分别实现 |
| Stage | 尚未实现演示编辑器 | 提供演示创建、幻灯片编辑与展示 |
| PDF | 可作为附件交给系统应用打开，无内置阅读或编辑器 | 在应用内打开已有 PDF，阅读、修改和保存；禁止空白新建 |
| 本地工作区 | 已有项目、文件树、标签、草稿恢复、移动与归档 | 新模块接入一致的文件与会话流程 |
| Git | 已有可选本地记录、历史和手动同步 | 文件保存、本地版本与远端同步分别反馈结果 |
| 中英文界面 | 当前主要为硬编码中文，尚无完整语言切换机制 | 提供中文与英文显示，采用第 3 节的名称与入口 |

Markdown 中的表格不是 Array 工作簿；富文本 Markdown 编辑也不等于已支持 Word。现有未来模块接口和 Page 类型草案不代表相应编辑器已经完成。

平台沿用既有计划：Windows 为首发平台；macOS 已有开发版交互检查，macOS/Linux 安装包另行验收。具体版本与检查范围见 [验证记录](VALIDATION.md)。

## 3 模块命名与语言显示

### 3.1 确定的名称和入口

| 内容类型 | 英文名称 | 英文创建入口 | 中文创建入口 | 中文类型标识 |
| --- | --- | --- | --- | --- |
| 文档 | Note | Note | 创建文档 | 文档 |
| 电子表格 | Array | Array | 创建表格 | 表格 |
| 演示 | Stage | Stage | 创建演示 | 演示 |
| LaTeX 数学片段 | Formula | Formula | 创建公式 | 公式 |
| PDF | 独立产品名待定，暂以 PDF 标识 | 无 | 无 | PDF |

PDF 使用独立的“打开 PDF”入口，英文为“Open PDF”。此前提出的 View 仍为候选，不作为已确认名称。

### 3.2 显示规则

1. 英文创建菜单直接显示 `Note`、`Array`、`Stage`、`Formula`，不拼接中文，不显示 `Note 文档` 等双语组合，也不添加 `Create` 或 `New` 前缀。
2. 中文创建菜单使用“创建文档”“创建表格”“创建演示”“创建公式”，不显示“创建 Note”等混合文案。
3. 中文类型标识使用“文档”“表格”“演示”“公式”；英文类型标识使用相应英文名称。工具提示、无障碍名称和操作反馈采用当前界面语言。
4. 语言只影响界面文案，不翻译正文，不修改已有文件名、扩展名、文档类型或保存内容。
5. 创建入口按实际可用能力出现。未实现的模块不能以可点击入口制造已经支持的印象。

现有 Markdown 模块暂时保留独立入口，英文为 `Markdown`，中文为“创建 Markdown”，类型标识为 `Markdown`。Note 与 Markdown 后续是否合并为同一产品入口另行确定，本次不据此转换或重新分类现有文件。

### 3.3 Formula 替代 Geek

- Formula 已替代当前用户界面中的 Geek。完整语言机制尚未实现，后续中文界面按上述规则显示“公式”。
- 新名称覆盖创建菜单、类型标识、提示、帮助和当前功能说明。历史验证记录可以保留当时使用的名称。
- 兼容已有 `.tex` 文件、草稿、最近文件和标签恢复数据。产品改名不要求更改已有文件，也不要求立即更改内部 `latex-math` 标识。
- Formula 继续处理数学片段，支持源码与对照视图。改名不增加完整 TeX 编译、任意宏包支持或 PDF 导出能力。

## 4 各模块功能要求

### 4.1 Markdown 现有能力

- 支持 Markdown 排版正文编辑、源码编辑和对照，切换视图保留内容与撤销历史。
- 支持常用标题、段落、列表、引用、代码、表格、任务列表、链接、图片与数学公式；未支持富文本编辑的结构保留原文，可切换源码处理。
- Mark 作为内容单元维护身份与局部字体、字号；移动保留身份，复制产生新身份，相关操作可撤销。
- 正文右侧提供标题目录、搜索、折叠与定位；内容块检查器提供次级操作。左侧继续管理项目和文件。
- 身份和局部样式随 Markdown 尾部元数据保存。只读打开普通 Markdown 不改写原文件；主动保存按现有规则写入元数据。

### 4.2 Formula 数学公式

- 新建独立数学草稿，输入 LaTeX 数学源码并实时渲染，默认对照视图，可切换源码视图。
- 无效或未完成的公式保留源码并显示错误，不丢失输入。
- 与 Markdown 使用独立编辑器和工具能力，不显示无效的 Markdown 块排版或正文目录控件。
- 保存使用现有 `.tex` 路径，接入草稿、撤销、标签、保存与版本记录流程。

### 4.3 Note 文档

目标为 Word 类文档的创建、编辑和排版。模块需要独立的数据模型、页面布局、编辑器和格式读写；`.docx` 的导入导出范围需按实际支持的内容逐项定义和验收。

当前 Markdown 的富文本能力可作为复用基础，但不能仅修改入口名称就视为 Note 完成。连续正文与分页布局、图片、表格、字体和页眉页脚等能力需在模块实施时明确首版范围。

### 4.4 Array 表格

目标为工作簿、工作表和单元格编辑。单元格的内容、值类型、格式与公式原文由表格模型管理，计算层负责公式解析、引用关系、重算和错误反馈，图表层负责数据绑定与展示。

`.xlsx` 读写、函数覆盖、公式复制和图表类型分别验收。Markdown 表格、通用 Mark 引用或 JSON 快照不能代替这些能力。沿用既有范围，当前规划不含筛选器和切片器。

### 4.5 Stage 演示

目标为创建演示、管理幻灯片、编辑页面内容与展示。需要独立的固定页面编辑和演示视图，以及 `.pptx` 格式适配；模板、动画、切换效果和导入保真范围在实施时单独确定。

页面草案仅提供复用边界，不代表 Stage 已实现。

### 4.6 PDF 阅读与修改

PDF 的起点必须是已有文件。基本流程为“打开 PDF → 阅读 → 按需修改 → 保存或另存副本”。

- 不提供“创建 PDF”“新建 PDF”“空白 PDF”或空白模板入口。
- 开始页、标签加号、文件菜单、右键菜单、快捷键和内部创建命令均不能产生无来源的空白 PDF 草稿。
- 取消打开、路径失效或读取失败时，不留下空白 PDF 标签或文件。
- 阅读不改写原文件。修改已有 PDF 后可以保存或另存副本；另存副本不属于从零新建。
- 阅读与编辑权限分开。无法编辑的文件或内容，应保留阅读能力并明确说明可操作范围。
- 编辑能力需按原文字、图片、批注和页面操作等实际支持范围验收，不能将文字提取或覆盖显示宣称为任意正文可编辑。

上述限制针对独立 PDF 文档的创建，不自动禁止已有 PDF 内的页面编辑。其他模块导出 PDF 沿用后续导出规划，需单独实现与验收，不能借导出入口生成无来源的空白 PDF。

## 5 共用工作区与数据要求

### 5.1 创建与打开

可新建的模块先创建独立草稿，首次保存再选择文件名和位置。取消首次保存保留草稿，不强制绑定项目。PDF 通过打开已有文件进入工作区。

当前首次启动和通用新建快捷键默认创建 Markdown；新的默认类型尚未确定。新模块接入时应明确默认行为，不能因用户正在阅读 PDF 就由通用新建动作生成空白 PDF。

### 5.2 标签与恢复

- 各标签独立保留编辑状态、撤销历史与视图布局，支持切换、固定、排序和重新打开。
- 关闭未保存内容时提供保存、保留草稿或取消；切换项目和退出前保护尚未保存的修改。
- 恢复草稿与磁盘内容冲突时保留双方，不直接覆盖。文件重命名、移动和归档继续遵守现有恢复规则。
- 语言、主题与布局切换不能造成文档修改、类型转换或撤销历史丢失。

### 5.3 保存与版本

- 保存时校验磁盘是否发生外部变化；检测到冲突时停止覆盖。
- 保存快照与继续输入的内容分别处理，较早的保存结果不能清除后续修改状态。
- 文件保存、本地 Git 提交和远端同步分别报告结果。Git 失败不抹去已经保存的文件；联网失败不阻止本地编辑。
- Git 由用户明确启用；自动版本默认阈值为正文净修改 500，可调整或关闭。现有文本计数规则不直接套用于未来二进制模块。
- 不强推，不混入无关文件或其他工具已暂存的修改。设备设置与恢复草稿不自动随文档仓库同步。

### 5.4 显示与操作

保留跟随本机、浅色和深色主题；布局适应窄窗口，常用操作支持键盘访问。工具栏按模块能力显示，避免无效控件。动效遵守系统减少动态效果设置，不改变编辑内容或抢走正文焦点。细节见 [设计规范](DESIGN-SYSTEM.md)。

## 6 实现边界

共享工作区负责项目、文件、标签、保存协调与窗口控制；各文档模块负责自己的模型、编辑、预览、命令和读写。二进制格式不能直接塞入现有 Markdown 字符串模型。

创建、打开、阅读、编辑和保存能力需要分别表达。PDF 应允许打开和阅读，在实现范围内允许编辑与保存，同时始终禁止无来源创建；这项限制必须在命令层生效，不能只隐藏菜单。

Mark 引擎维护内容身份和事务，页面布局、表格计算、图表和格式适配分别承担自身职责。技术契约与现有草案见 [架构约定](OOPS-ENGINE-ARCHITECTURE.md)。

| 层次 | 要求 | 状态 |
| --- | --- | --- |
| 当前基线 | Markdown、数学片段、本地项目、草稿、标签、Git、主题与导航 | 已有实现，具体检查范围见验证记录 |
| 本次名称调整 | 程序、窗口及安装包使用 MarkFlow；Formula 替代 Geek | 源码与打包配置已完成；保留旧数据与升级标识，验证范围见验证记录 |
| 后续命名与语言 | Note、Array、Stage 命名；中英文入口与类型文案 | 需求确定，待相应模块与完整语言机制实现 |
| 新模块 | Note、Array、Stage、PDF 内置阅读与修改 | 后续各自实现模型、编辑器、格式读写与验收 |
| PDF 创建限制 | 所有新建入口及命令禁止空白 PDF，打开和修改已有 PDF 正常工作 | PDF 接入时必须满足 |
| 既有后续计划 | 全文搜索、历史差异、图片管理、打印及 PDF/HTML 导出等 | 继续由开发清单跟踪 |

完整 TeX 编译、多人实时协作和数据库仍未纳入当前开发范围。AI、插件等保留为后续需求，不作为本次命名调整的交付内容。

## 8 验收标准

以下覆盖已实施调整和后续功能，实际通过范围以验证记录为准。

1. 英文创建菜单在相应模块可用时，精确显示 `Note`、`Array`、`Stage`、`Formula`，没有中文后缀或额外创建前缀。
2. 中文对应入口精确显示“创建文档”“创建表格”“创建演示”“创建公式”；类型标识与提示遵守同一语言规则。
3. Formula 迁移完成后，当前用户界面不再出现 Geek；旧 `.tex`、草稿和标签会话仍能打开，内容与类型保持正确。
4. 切换界面语言后，文案一致更新，正文、文件名、扩展名、修改状态和撤销历史保持正确。
5. 新建菜单只提供已实现且可创建的类型。Note、Array、Stage 必须有实际模型和编辑能力，不能创建伪装格式的 Markdown 文件。
6. PDF 在开始页、标签加号、文件菜单、右键菜单和快捷键中均无空白创建入口；直接调用创建命令也应拒绝。
7. 打开已有 PDF 可进入阅读流程；取消或打开失败不创建空白文件或残留草稿。
8. 支持的 PDF 修改可保存并重新打开；另存副本保留原文件。只读阅读不改变源文件。
9. PDF 当前不支持的编辑操作给出明确反馈，不破坏原文件，不把视觉遮盖当作原内容已删除。
10. Markdown 与 Formula 的编辑、布局切换、撤销、草稿恢复、首次保存和文件冲突保护保持可用。
11. 新模块按各自格式验证打开、编辑、保存、重开与兼容范围；仅完成名称或菜单不算模块交付。
12. 发布时分别记录目标平台、源码版本、构建和安装包验收；历史验证不能替代新实现的验证。

## 9 后续需确定的规格

- PDF 的独立英文产品名；目前保留 PDF 标识。
- Note 与现有 Markdown 的入口关系，以及首次启动、通用新建快捷键的默认类型。
- Note、Array、Stage 的首版格式兼容范围，以及 PDF 的具体编辑操作范围。
- 语言选择方式与默认语言规则；无论入口如何选择，第 3 节的显示规则保持一致。
