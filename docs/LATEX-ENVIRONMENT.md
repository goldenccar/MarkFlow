# 论文编译环境

## 在应用内安装

打开新标签，选择 **LaTeX 论文**，点击 **安装论文环境**。完整安装包附带离线环境，安装过程会校验文件、展开到当前用户的数据目录，再切换为新环境。无需管理员权限，不修改系统 PATH，不替换电脑上已有的 TeX。

轻量安装包不附带环境，使用 **导入离线环境包** 选择与当前应用匹配的 `.mftex.gz` 文件。文件必须符合应用内置的版本、操作系统、处理器架构和 SHA-256 清单。不能直接导入任意 TinyTeX 压缩包或自行修改的编译器。

当前 Windows 环境包已在本地生成，尚未发布在线下载地址。完整包构建时从 `vendor/tex/cache/` 带入；应用不会访问一个不存在的下载地址，也不会在用户机器上运行 `tlmgr` 下载缺失包。

- 安装过程中可取消。正在使用的旧环境不受影响；本次未完成的目录会清理。
- 校验或验证失败会显示原因，可重新选择完整文件后重试。
- 成功升级后保留上一环境，可使用 **回退上一版本** 切换回来。
- 安装期间至少预留约 1 GB 空间；升级时还会保留旧版本的占用。
- 在应用运行的当前用户下安装，各用户的环境互不影响。

## 校验、安装和回滚

运行时安装在应用用户数据目录的 `paper/environments/` 下。每次安装使用独立阶段目录，完成以下步骤后才更新 `active.json`：

1. 匹配应用内置清单中的平台、架构、包大小和完整包 SHA-256。
2. 校验包内清单 SHA-256，并拒绝越界路径、重复路径、目录冲突和越界符号链接。
3. 流式解压，按文件逐项验证 SHA-256。不会把整个环境一次性读入内存。
4. 检查所需工具，并实际启动 XeLaTeX 获取版本。
5. 写入安装回执，原子切换当前版本，保留上一版本。

启动检查用于发现环境缺失或不能启动，不能代替模板编译验收。发布验证另外执行真实中文字体、参考文献、源包往返与 PDF 文本检查，见下文。

完整文件校验发生在安装时。后续启动会检查安装回执并探测编译器，不会每次编译都重新计算全部文件的哈希，也不声称持续防止本机同权限用户篡改环境。

环境包是 `gzip` 压缩的固定格式：`MFTEX01\n` 标识、四字节大端清单长度、JSON 清单、按清单顺序存储的文件内容。清单记录版本、平台、架构、包修订号、许可文件、来源及每个文件的路径、长度、权限和 SHA-256。解包后才创建经过约束的内部符号链接。应用不调用外部解压程序执行未知内容。

旧环境与新环境均不写入全局 PATH。编译时使用受控工具路径和项目独立缓存；这降低配置冲突，不是操作系统沙箱。来自他人的论文源码仍需经过应用的信任确认。

## 构建者准备与冻结

`prepare:tex` 仅供构建和开发机器准备素材；最终用户使用上面的应用入口。

```powershell
npm run prepare:tex
node --import tsx scripts/package-tex.ts
```

冻结脚本将已准备环境打包到 `vendor/tex/cache/`，同步生成完整 manifest、catalog 和应用内的受信任清单。可使用 `--root`、`--output`、`--catalog`、`--provenance` 指定构建路径。内容变化时必须增加 `--version`；同一个版本不能覆盖为另一份内容。

基础素材来自 [TinyTeX 官方 v2026.10 发布](https://github.com/rstudio/tinytex-releases/releases/tag/v2026.10)。Windows 原始文件为 `TinyTeX-windows-v2026.10.exe`，其 SHA-256 为 `e23dcc65026b96a2c34bbd793087f64e6b6e9173c20483fe875050251e3994e1`。补充宏包的准备阶段使用 CTAN；最终发行物冻结完整文件和包修订号，用户安装时不再依赖 CTAN 的变化。构建阶段的 CTAN 仓库并非历史快照，新一次准备必须重新冻结并验收，不能据此声称从网络永久可重建相同字节。

环境保留 `LICENSE.TL`、`LICENSE.CTAN`、Ghostscript 的 `COPYING`、Adobe 映射资源的许可文件，以及各包原有的 `tlpkg/tlpobj/` 许可和来源元数据。TeX 组件各自适用其许可证，不能将整个环境视为应用自身许可证的一部分。分发应保留完整环境中的原有许可及来源信息。

macOS 的准备和验收入口支持本机执行；冻结包按实际机器架构生成。Windows 包不能在 macOS 导入。本版本没有生成已验收的 macOS 环境包，也未把 Windows 的结果标为 macOS 通过，具体见 macOS 验收文档。
