# M5 四组完整成本实验协议

状态：**协议已定义，四组对照尚未实测。** 本文件不是节省比例、效率排名或商业收益结论。编译器单测通过、文件生成耗时短或样例较简洁，都不能代替该实验。

## 同一个任务，四种表达路线

| 组 | 允许的成熟做法 | 必须计入的组内工作 |
| --- | --- | --- |
| A · Mark 内容＋呈现 | 内容身份、显式选择、当前编译器和主题 | 内容建模、Mark ID / 引用维护、呈现选择、编译器与模板准备 |
| B · Markdown＋模板 | 成熟 Markdown 解析器与合理模板；允许稳定命名锚点 | Markdown 资料整理、模板 / 锚点维护、两种输出的适配 |
| C · 简洁 JSON＋布局规则 | 精简的数据 JSON、可复用布局规则、正常校验 | JSON schema / 转换、规则准备、共享数据定位和变更 |
| D · 高层 DOCX/PPTX API | docx、PptxGenJS 等高层 API；允许函数与共享常量 | 程序结构、参数与共享事实组织、写出和验证脚本 |

不得把 D 组降为手写原始 OOXML，或故意禁止其复用函数、共享数据和模板。原始 OOXML 可列为附加对照，不能替代四组中的正常高层 API 路线。四组均可使用相同模型 / 工具辅助，但必须完整记账；若只给一组预制模板，模板的准备成本要单独计入，不能当作免费起点。

## 固定条件与任务序列

使用同一份虚构事实、图片、字体、主题目标、2 页报告要求与 4 页演示要求。基准样例取自 [examples/compiler](../../examples/compiler/README.md)，固定来源文件及图片 SHA-256。四组使用同一台机器、Node / Office 版本、字体文件、docx / PptxGenJS 版本、目标应用和验收标准；记录实际配置，不用“同等环境”代替版本信息。

1. **首次生成**：从原始事实包得到合格的 DOCX 与 PPTX。报告有两节明确分页，演示有封面、正文、图文和表格四页。包含中文、强调、列表、链接、本地图片和 4 × 3 表格。
2. **共享事实变更**：把共享事实“12 个城市”改成“15 个城市”，只提出一次变更要求。报告与演示所有应出现的位置必须更新，其他事实和对象保留。记录修改了几处源数据、呈现和程序，不能只统计最后一次成功运行。
3. **故障定位**：分别输入未知版本 / 结构、断裂引用、缺失素材与超量文本。检查能否定位原因、阻止不完整输出，以及修复到合格所需的全部尝试。
4. **原生编辑复核**：在同一办公应用中修改一段中文、一个表格单元格和图片位置，保存、关闭并重开。不能把整页截图当作可编辑产物。

首次开发与既有系统的重复使用分开报告：冷启动包含 schema、模板、工具链与任务适配准备；稳态只在四组均已有等价可用基础后开始。记录每一项一次性投入，并同时给出未摊销总成本与按明确使用次数 N 摊销的结果，不能把一次性投入隐藏在任意大的 N 里。

## 完整成本账本

每一次尝试保留时间、组别、操作者、任务阶段、输入 / 输出文件摘要、调用记录和失败原因。不得在成功后删掉失败运行。若使用模型，固定模型、推理档位、上下文策略、工具权限与可用文档；提示词可以适配各路线，但都计入。

| 项目 | 记录方式 |
| --- | --- |
| 模型输入 | 系统 / 开发者 / 用户提示、样例、schema、源码、工具返回和重复上下文全部计入；单列缓存输入 |
| 模型输出 | 回答、代码 / JSON / Markdown、工具参数及可获取的推理用量；分别报告，不只统计最终内容字符数 |
| 工具往返 | 调用次数、返回规模、CPU / 墙钟时间；失败、重试、重新读取都保留 |
| 人工时间 | 准备、写提示 / 输入、等待、审校、定位问题、修正、重新生成、应用内复核分别计时；区分主动操作与被动等待 |
| 一次性与维护 | schema / 模板 / 程序实现、依赖安装、熟悉工具、适配器升级及模板修改；单列原有可复用资产 |
| 产物质量 | 首次通过率、达到全部合格条件的时间、缺失 / 错误 / 越界数量、人工修正次数、共享事实更新完整率 |
| 金额 | 采用实验当天可核实的模型 / 计算单价；人工单价仅在明确给定时折算，不能自行假定 |

总成本应至少能拆回：一次性准备＋本次模型调用＋工具执行＋人工审校修正＋维护分摊。若某供应方不返回完整 token 数据，写“不可获得”，并保留可核对的日志和代理指标；不能把缺失数据记为零。代码行数、JSON 长度与 token 数可作为解释变量，但不能单独代表总成本。

## 公平执行与结果展示

- 先写清合格条件，再运行；四组不得使用不同的最低字号、图片质量、页数或可编辑要求。
- 使用统一事实包，但不要让同一操作者总按 A→B→C→D 顺序执行。预先确定轮换顺序，记录学习效应；熟悉度差异单列。
- 保存每组所有尝试。失败无法修复也属于结果，不从平均值中剔除；超出预先规定的时间 / token 上限记为未完成。
- 多轮结果报告每组样本数、中位数、范围及失败次数。一次运行只能称为一次样例观察，不能外推稳定优势或百分比节省。
- 同时呈现冷启动、稳态与共享事实变更三类结果。任何“更省”结论都要说明省的是 token、人工时间、总金额还是修改范围，以及对应质量前提。
