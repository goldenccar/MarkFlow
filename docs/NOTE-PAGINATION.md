# Note：模板配置与实时分页设计

更新：2026-10-30（Asia/Shanghai）。状态：需求与实施设计，尚未实现。此文不改变现有 Markdown/Formula 编辑器，也不把当前生成弹窗当成 Note 工作区。

## 1. 产品交互

Note 文档标签提供左右两区：左侧编辑内容和结构，右侧显示按真实尺寸分页的连续页面栈。右侧包括正文、跨页、页边距、页眉、页脚和页码，支持独立滚动、缩放、适合宽度与指定页跳转。左侧不是强制 JSON 编辑器；高级源码视图按模型支持开放。

“模板配置”是独立、非模态页面/标签，可在创建文档前打开，也能与文档会话同时保持打开；宽屏可并排呈现。常规用户通过表单完成配置，JSON 是相同配置的高级查看/编辑及导入导出形式。两种编辑方式使用同一份配置与校验，不维护互相漂移的两份状态。无效 JSON 保留输入并显示位置，不能清空有效配置。

| 模板配置 | 默认操作 |
| --- | --- |
| 模板 | 标准文档、商务报告、公司抬头纸；复制为我的模板 |
| 页面 | 纸张、横竖向、四边边距、页眉页脚距离；高级分节 |
| 样式 | 正文、标题层级、列表、表格、图注的字体/字号/间距 |
| 页眉与页脚 | 左/中/右区域选择文字、图片或字段；分隔线、间距 |
| 图片 | 选择本地 Logo，位置、最大尺寸、等比适配；常规入口不填写素材路径 |
| 字段 | 文档标题、作者/组织、文档编号、固定生成日期、当前页/总页数；动态日期必须显式选择 |
| 特殊页面 | 首页不同、奇偶页不同、封面隐藏页码、正文起始编号 |

模板草稿可即时用于当前关联文档预览，但不能静默改变其他已打开文档。“应用到当前文档”“保存为我的模板”“设为项目默认”是不同动作。保存产生模板版本；新文档可继承项目默认，旧文档继续引用原版本，显式升级可撤销。

右侧独立阅读是默认行为：用户停在第 8 页，左侧输入、选择或滚动不强行切换右侧页码。只在明确点击“定位当前 Mark”时联动。重排用视口首个可见 Mark、片段内文本位置和相对视口偏移恢复位置；该 Mark 删除时回退到邻近存活 Mark，不使用全文滚动百分比。缩放只改变显示，不改文档字号、页数或分页宽度。

## 2. 当前基础与缺口

- 已有：稳定 Mark ID、事务/撤销、Markdown 富文本适配、独立 Formula、项目/标签/草稿，以及后台 DOCX/PPTX 生成。
- 缺少：Note 会话/编辑器、模板持久化/配置页、字段语义、真实页眉页脚/Word 分节、浏览器分页运行时及双侧独立状态。
- 当前 `NotePresentation.sections` 只有 Mark 分组与强制换页，写出时仍合为一个原生 Word section。不能直接把旧字段解释为支持每节不同页眉、横竖向或编号的完整分节。
- `src/engine/page.ts` 只是设计类型，当前没有页面运行时。本次明确启动受限的 Note 流式分页路线；不同时实现 Stage 编辑器、Array 计算或任意 PDF 重排。

## 3. 共用排版输入与格式边界

统一输入为：Mark 文档快照＋呈现顺序/真实分节规则＋模板版本＋字体和素材清单。规范化一次，生成明确的页面尺寸、样式、资源和断页约束，分别交给浏览器分页适配与 DOCX 写出器。预览和导出禁止各自复制一套默认值。

Mark 核心继续只处理内容身份、引用和事务。页眉文字、Logo、字段使用可引用的内容；模板定义重复区域和位置。跨页段落生成派生片段，片段引用原 Mark 与文本范围，不拆成新的内容 Mark；同一 Logo 在多页重复显示，不创建多份独立图片内容。

模板配置应版本化并只接收受限声明字段：页面、命名样式、重复区域、字段绑定、资产和适配规则。不能运行任意 JS、CSS 回调或自由表达式。新分节/字段能力扩展规范版本，旧输入仍按旧语义解释；迁移必须显式测试。

样式按“模板默认 → 文档覆盖 → Mark 显式覆盖”解析。另提供“本次统一使用模板样式”，不静默清除源内容里的局部字体。模板素材由本地选择器授权后保存为模板资产，使用相对路径和摘要，不只保存作者电脑的绝对路径。缺失字体或图片显示诊断，保留上次有效结果。

Note 须有独立模型与会话，通过文档模块契约接入文件、草稿、标签和历史。先保存可重开的结构化源及模板关联，再导出 DOCX；DOCX 导入和原文件保真往返单列支持矩阵，不能因可以导出就宣称可以打开编辑任意 Word 文件。

## 4. 自适应算法

### 4.1 先确定页面可用区域

1. 等待字体就绪、图片解码及尺寸校验，解析样式和首/奇/偶页配置。
2. 页眉页脚文字按各槽位宽度换行，Logo 在最大宽高内等比适配；计算所需高度和内边距，设置合理高度上限。
3. 正文上界取“配置上边距”和“页眉位置＋高度＋安全间距”的较大值；下界对页脚同理。正文宽度扣除左右边距及明确的装订留白。
4. 页眉/页脚过高、正文剩余空间不足时报告配置冲突，不无限挤压正文。首页、奇偶页分别检查，不假设只有一套区域。

### 4.2 按内容寻找合法断点

- 段落使用浏览器排版的实际行盒进行断行/分页，遵守孤行寡行约束；不能用“字符数×字号”估算中文字形宽度。标题优先与后续正文同页。
- 内容放不下当前页时先换页；超过一整页的段落按行拆成片段。手动换页和明确章节规则优先，不强制每个 Mark 占一页。
- 图片默认等比缩小到可用宽高，不拉伸；图片和图注优先成组换页。可读下限或用户指定最小尺寸无法满足时给出诊断，不丢图、裁正文或偷偷缩小全篇字号。
- 表格列宽结合配置权重与内容最小宽度分配，单元格内换行，跨页重复表头。初版必须通过行间跨页；超高单行、合并单元格等未验证结构明确诊断。行内拆分和横向分节只能在模板允许且实现已验证时启用，不能暗中改变页面方向。
- 页眉页脚按页面类型重复，正文流与重复区域分开计算。文档编号、标题等从明确绑定读取，页码/总页数保留字段语义。
- 总页数完成后解析计数，预留字段宽度。若实际位数变化会影响布局，进行有次数上限的重新排版；不收敛则报告，不能死循环或显示错误页数。

适配器共享可表达的 `keep-with-next`、孤行寡行、图片比例、表头重复、分节/换页等语义；不能把浏览器的一切 CSS 当成 DOCX 都能实现的能力。[W3C 分页断点规则](https://www.w3.org/TR/css-break-3/)

## 5. 右侧预览的实现选择

优先以 Paged.js 做受限原型：将规范化输入转换为可控 HTML/CSS，使用其分页与页边区域能力生成连续页面栈。Vivliostyle 是原型不达标时的备选；不同时引入两套分页器。必须先验证中文长文、字体、长表格、Logo、页码和重排，再锁定依赖版本；本次设计未安装或选定运行依赖。[Paged.js 工作方式](https://pagedjs.org/en/documentation/4-how-paged.js-works/)

`docx-preview` 可用来探索已有 DOCX 的结构显示，但不作为本需求的实时分页主链：上游明确未实现实时重新分页，且字段支持有限。把 DOCX 转成 HTML 并展示已有断页，不能替代编辑过程中的自动流式分页。[上游限制](https://github.com/VolodymyrBaydalka/docxjs#breaks)

必须区分两种可见状态：

- **实时排版预览**：使用当前 Mark＋模板的浏览器分页结果，支持持续编辑、跨页、独立阅读。它是真实分页，仍不天然等于 Word/WPS 的最终分页。
- **目标应用校对**：对指定源快照生成 DOCX，再通过已验证、用户可用的目标排版器生成校对预览，注明软件版本、源修订和更新时间。Word 的固定格式导出接口可作为一种路径；不是每次按键都启动 Office，不把 PDF 校对结果称为可编辑 DOCX，也不擅自安装新办公软件。[Word 固定格式输出](https://learn.microsoft.com/en-us/office/vba/api/word.document.exportasfixedformat)

若目标是与 Word 完全相同的分页，必须以该 Word 排版器的输出为依据。浏览器分页预览不能承诺与不同版本 Word/WPS 跨应用像素一致。初版不做任意 DOCX 模板的无损导入；先提供可配置的标准模板。

## 6. 性能、取消与状态保护

连续编辑可先按 200–300 ms 合并布局请求，输入法组合期间不提交中间状态。文档、内容、模板、字体和素材版本共同组成布局键，只接收最新布局键的结果；快速切模板、切文档和关闭会话时取消或丢弃旧任务。

后台先构建下一份页面，再整体提交有效结果，避免清空闪烁。失败保留旧预览并标注“预览尚未更新”；不落盘源文档、不改变 dirty、不创建 Git 记录、不重置撤销或光标。

语义解析和资源准备可以使用 Worker；DOM 测量与分页需要浏览器文档，不能仅写成 async 或放入普通 Worker 就声称解决了卡顿。先在独立受控预览文档中测量；若与编辑器争抢主线程，则隔离到独立 Electron 预览 WebContents，并继续限制脚本、导航、资源访问和 IPC。

先实现可取消、可验证的完整重排。随后才依据稳定断点、页首/页尾 Mark 范围和剩余空间摘要，从受影响页向后重排；只有输入、布局状态与后续页都吻合才复用尾页。字体、边距或全局样式变化允许全篇失效。不能假定第三方分页器的内部断点 API 稳定。

可见页附近保留 DOM、远处保留页面摘要是显示优化，不等于只排可见页；未完成全篇分页时总页数必须显示“计算中”，不能伪造完整页数。对 10/50 页及 100/1,000 Mark 分别测输入到帧、首个预览、完整重排、过期任务和内存，而非只报编译用时。

## 7. 完成标准

1. 无需手写 JSON，能配置并保存带 Logo、标题、页码的模板，重新启动后在另一文档复用；项目默认与旧文档模板版本互不混淆。
2. Note 能新建、编辑、保存、重开，模板关联、Mark ID、撤销、草稿和冲突保护保持一致；不能以新增菜单代替完成。
3. 10 页中文样例包含标题、段落、列表、图片、长表格、页眉页脚及首页不同。增删内容确实增减页面；输出文本不缺失、不重复，跨页片段不改变 Mark 身份。
4. 右侧停在后续页，左侧滚动/输入不强制跳页；重排维持阅读锚点。缩放、窄窗和焦点切换不修改正文。
5. 字体/图片缺失、配置冲突、连续修改取消、页数位数变化及布局错误保留编辑内容和旧有效结果，提示指向模板字段或 Mark。
6. 相同输入/模板生成 DOCX，并在声明版本的目标办公软件核对文字完整性、样式、原生页眉页脚/图片/字段和分页差异。浏览器结果与目标应用结果分别记录，不能混作一次验收。
7. 持续编辑和模板切换期间测试性能与内存；原 Markdown/Formula 的保存、输入法、导航、性能及撤销不得因 Note 分页功能回退。未通过前不把 Note 创建入口标为完成。
