# OopsMD 界面设计规则

更新：2026-10-26。用于维护当前桌面编辑器的视觉一致性；数值以 `src/renderer/app.css`、`editor-preview.css`、`block-editor.css` 为准。正文、编辑与文件功能沿用现有实现。

## 层级与尺寸

- 正文是主区域，标签负责文档切换，工具栏负责当前编辑，侧栏负责项目/文件/Mark 定位。
- 当前文件使用中性底色；当前 Mark 使用浅强调底和 2 px 侧标。项目名称只在项目入口完整呈现，树内入口显示“根目录”；新建文件夹与树视图切换同行。
- UI 基础字体为 Segoe UI Variable Text / Segoe UI / Microsoft YaHei UI，基础字号 13 px。标签与工具 12 px，辅助状态 11 px；10 px 仅用于紧凑的类型标记等辅助信息。正文字体、字号、行距仍服从用户设置和 Mark 覆盖。
- 默认正文为 16 px、1.8 行距、780 px 内容宽度。rich 与阅读预览共享排版：H1 2.15 em，H2 1.5 em，H3 1.2 em；普通标题 650 字重，H1 700；段后距 .95 em。代码与公式保持各自的字体和布局规则。

| 项目 | 当前尺寸 |
| --- | --- |
| 原生标题栏 / 文档栏 / 工具栏 | 40 / 44 / 44 px |
| 状态栏 | 28 px |
| 侧栏 | 240 px；窗口不超过 1020 px 时为 212 px |
| 文件 / Mark 行 | 最小 32 / 27 px；树层级缩进 16 px |
| 控件 | 常规 32 px；工具栏紧凑控件 28–30 px |
| 常用间距 / 圆角 | 间距以 4/8 px 为基准，组间 12/16/24 px；基础圆角 7 px，紧凑控件 4–6 px |

正文横向留白为 20–48 px，顶部为 32–56 px，随窗口变化；对照模式收紧到横向 24 px、顶部 32 px。内容按最大宽度居中，长代码和表格在自身容器滚动。长文件名省略但保留完整 title，不能挤掉保存和窗口控制。

## 色彩 token

`--bg` 为正文，`--shell` 为控件底，`--sidebar` 为导航；`--surface-raised` 用于浮层。`--text`、`--muted`、`--subtle` 区分正文、辅助和细节；`--line` 与 `--outline` 区分分隔线和控件边界。强调、悬停、焦点、选择分别使用 `--accent`、`--hover`、`--focus`、`--selection`，不要互相代替。

| Markdown 夜间 | #222423 | #1b1e1c | #e8ebe8 | #b0d1c1 / #2e4036 |

Markdown 使用近中性底色，墨绿集中在选中与焦点；Geek 使用冷蓝灰。标题栏保持共同的中性窗口底色，与原生 caption 区一致。阴影只用于浮层和轻微控件层次；分区主要依靠留白、底色和细线。警告/危险色保留明确语义，保存状态同时提供文字，不能只靠颜色识别。

## 渐进收纳与反馈

工具栏断点按主内容区域宽度计算：不超过 1100 px 时搜索框收为图标；960 px 时上/下标等进入“更多排版”；880 px 时布局改为图标；800 px 时继续收纳下划线、删除线，保留加粗/斜体；580 px 时格式按钮统一进入菜单。入口名称、快捷键和处理逻辑保持。Geek 隐藏本就不可用的 Markdown 格式按钮。

普通状态过渡使用 `--motion: 140ms cubic-bezier(.2,.7,.2,1)`，仅过渡颜色、边框和阴影；格式菜单为 120 ms、3 px 的淡入。避免持续动画、滚动接管和正文位置动画。`prefers-reduced-motion: reduce` 关闭动画、过渡和平滑滚动。键盘焦点保留 2 px 外框；hover 不能成为操作入口唯一可见的条件。

## 两轮自检与停止条件

1. **第一轮：结构与规则收敛。** 核对标题栏、文档栏、工具栏和正文关系；统一 rich/preview 排版，区分文件/Mark 选中状态，设置渐进收纳与短动效。用不同窗口尺寸、两种内容模式及明暗主题检查长标题、表格、公式和菜单。
2. **第二轮：实际截图复审。** 检查 Markdown 1440×1000、920×620、夜间 1100×760，以及 Geek 1440×1000。发现侧栏项目名称重复、夜间底色过绿、Geek 留有整排不可用按钮，随后压缩侧栏标题、降低夜间底色偏色、隐藏 Geek 无效格式组。后续验收仍针对真实渲染结果。

停止条件是：**没有明显层级、可读性、裁切或状态反馈问题，且功能与性能检查通过。** 不为主观“更精致”无限调整，不用几何检查替代真实截图，也不用截图替代交互检查。最终检查结果和性能数字统一记录在 [VALIDATION.md](VALIDATION.md)，本文件不推测成绩。

## 功能边界与参考依据

本轮调整颜色、尺寸、排版、对齐、视觉收纳和反馈，不改变文件格式、Mark 身份、撤销、草稿、保存/Git、项目权限或窗口关闭流程。继续保留原生窗口拖动/缩放/caption、快捷键和菜单。没有增加 Page、PDF、AI 或其他功能承诺，也没有引入新的运行依赖。

官方标准用于建立检查角度，**不代表参赛认证，也不保证获奖**：

- [Awwwards Evaluation System](https://www.awwwards.com/about-evaluation/)：设计 40%、可用性 30%、创意 20%、内容 10%；本应用据此检查一致性、操作效率、Mark 交互辨识度与文案准确性。
- [Webby Judging Criteria](https://www.webbyawards.com/judging-criteria/)：参考 Apps, Software & Immersive 中的内容、结构导航、视觉、功能、交互、执行、创新及整体体验；视觉质量须服务实际使用，不能只检查首页或静态外观。
- [FWA 官方宗旨](https://thefwa.com/about/about-fwa/)：参考前沿创意、创新与进步的方向；本应用把辨识度放在内容定位和编辑反馈，不据此追加展示性特效。未使用未经官方确认的分项评分比例。
