# MarkFlow 界面设计规则

更新：2026-10-28。用于维护当前桌面编辑器的视觉一致性；数值以 `src/renderer` 下对应组件的样式与布局逻辑为准。

## 主题与细节复审（2026-10-28）

- 主题偏好与显示颜色分离：持久化 `system/light/dark`，编辑器只接收解析后的 `light/dark`。renderer 监听系统配色媒体查询；原生窗口监听 Electron `nativeTheme.updated`，不改操作系统设置。
- 顶部主题入口显示当前选择，菜单用等宽图标列、左对齐文案和右侧勾选。菜单支持完整键盘退出与焦点恢复；窗口尺寸或布局变化时关闭。
- UI 字体和等宽字体集中为 token；工具栏图标、字号、按钮高度统一。文档类型以低强调标记呈现；标签焦点使用内描边，禁用控件不再响应悬停。
- 设置分为外观、阅读、版本记录，统一字段留白；滑杆采用 3 px 轨道、12 px 滑块和键盘焦点圈。窗口不超过 1100 px 时，设置面板作为右侧浮层；设置/Git/历史与固定目录不同时挤占正文。
- 设置与工具栏共用 `SelectControl`：保留原生 select 的选项与键盘行为，关闭原生箭头绘制，使用统一图标和右侧文字留白。箭头不拦截点击，禁用态同步变淡。
- 目录根标题与子级区分字重，整行响应悬停，焦点不被滚动容器裁切。搜索支持清除、空结果恢复和方向键导航；临时目录按内容高度展开，固定目录满高；主区不超过 760 px 时缩为 224 px。
- 本次按 Awwwards 官方评审中可复用的可用性、可读性、对比度、性能与最佳实践逐项检查：[官方检查指南](https://www.awwwards.com/mobile-excellence-guidelines.pdf)。桌面编辑器保留阅读优先的布局，不加入无任务用途的滚动特效。检查结果记录于 VALIDATION；不使用主观打分作为获奖或认证结论。

## 当前实现：模块、文档导航与布局动效（2026-10-28）

文档外壳与导航样式分别位于 `document-workspace.css` 与 `document-navigation.css`；布局动效入口为 `useWorkspaceMotion.ts`。下方基础规范与本节保持一致，历史验收数字单独保留。

### 窗口与文档模块

- 窗口外壳管理项目、文件、文档标签、保存与窗口控制；编辑器和预览由文档模块提供。标题栏仍保留 macOS 原生红黄绿按钮及其安全区域，Windows caption 沿用系统控制。
- 侧栏右边界以 1 px 细线贯通到标题栏顶部，坐标取自同一个 `--sidebar-width`。顶部线与侧栏使用相同的位移、透明度端点；收起后不在 macOS 窗口按钮安全区留下孤立分隔线。
- 标签在 40 px 标题栏内垂直居中，高 30 px，四角统一为 7 px；选中态使用完整柔和边框，与下方正文之间保留留白。标签条两侧各留 8 px 外间距，滚动时也不贴侧栏分隔线；标签之间用 4 px 间距区分，取消额外竖线。侧栏开关、新建按钮与标签共用中心线，固定标签沿用相同外形。
- 固定标签仅在能保留一个完整普通标签时保持吸附；空间不足则整条横向滚动，避免固定区遮住活动文档。活动项定位只滚动标签条，不移动外层容器。
- 当前注册 Markdown 与 Formula 两个模块；每个模块声明可用布局、编辑器、预览、内容初始化和目录能力。工具入口根据能力显示。Markdown 支持实时块编辑、源码、对照、目录和块格式；Formula 使用数学源码与公式预览，不挂载 Markdown 的富文本编辑器及块工具。
- Word、表格、PDF 仅预留独立文档类型与读写接口，尚无可用编辑器。后续各自提供数据模型、编辑视图与格式读写，不能靠增加模式按钮或复用 Markdown 字符串来宣称已支持。

### 左侧项目栏与右侧文档导航

- 左侧只承担项目与文件定位；保留设置和 Git 入口。文档目录从左侧移到正文右侧，避免项目结构与正文结构混为一列。
- 右侧默认保留窄导航入口。存在至少两个标题时显示标题刻度，悬停或键盘聚焦可临时展开；点击入口可固定。固定面板宽 248 px，占用正文旁空间；临时面板浮在正文上，不改变编辑区宽度。
- 并排固定取决于正文主区宽度：普通布局至少 600 px，对照布局至少 900 px。低于阈值时改为浮层，保留固定偏好；尺寸恢复后自动回到并排布局。关闭该浮层仅隐藏本次展示，显式“取消固定”才更新偏好。
- 目录按真实标题层级组织，支持搜索、折叠、当前标题标记和键盘定位。目录显示标题；内容块通过二级入口查看，不再把普通段落和整个列表当作目录条目常驻展示。无标题时显示简短说明。
- 关闭、取消固定和鼠标移出行为区分处理；菜单与搜索拥有焦点时不应因鼠标离开而消失。关闭面板恢复导航入口的键盘焦点。

### 布局动效与性能约束

- 侧栏展开／收起、右侧导航固定／取消固定统一调用 `transitionLayout`。先读取少量可见容器的位置，再同步提交一次布局状态，最后读取终点；其余 190 ms 只通过 Web Animations 的 `translate3d` 与 `opacity` 完成过渡。
- 禁止给侧栏宽度、标题栏的 `width`、`min-width` 或 `padding` 添加逐帧 CSS 过渡。侧栏内容维持固定宽度并绝对定位，外层占位立即切换；关闭时内容仍能完成滑出。正文和文字不做缩放，不截图复制整页参与动画。
- 主区、编辑区、正文内容与标签栏的位移按父子关系抵消，避免嵌套元素被重复平移。正文最终宽度在布局提交时确定，浏览器可在该时点重新排版；这不等于已经证明浏览器只执行一次 Layout 事件。
- 动画期间设置 `data-layout-animating` 并发布 `workspace-layout-motion` 事件。内容块手柄暂隐并暂停位置测量；结束后恢复测量。手柄的连续位置放在 ref 中，通过 `translate3d` 更新，不以每一帧坐标驱动 React 渲染。
- 连续点击从当前视觉位置接续；窗口缩放、组件卸载及减少动态效果设置会结束现有动画并清理状态。`prefers-reduced-motion: reduce` 直接应用最终布局。
- 主题配色仍采用 160 ms 过渡；菜单、临时导航使用短时淡入和位移。任何主区动效不得改变原生窗口按钮位置，也不得夺走正文焦点或修改文档内容。

### 查找、字段与弹窗

- 工具栏只放查找入口，查询输入、计数、前后跳转与关闭集中在下方独立查找行。切换文档或编辑布局时，查询、编辑器匹配标记和计数一起清空，避免把上一个视图的状态带到新视图。
- 标签菜单与排版菜单支持方向键、Home / End、Enter、Esc、Tab，以及退出后的焦点恢复；尺寸变化时重新定位或关闭。Esc 由当前菜单、选择控件、查找或对话框优先处理，外层导航不重复处理同一次按键。目录查询非空时，Esc 先清空查询。
- 阈值字段使用字符串草稿，输入框与显式保存按钮同排；点击保存或按 Enter 时校验正安全整数，失焦不提交。保存时禁用输入及按钮并阻止重复提交；成功后以勾选及已保存文字反馈。无效值不调用保存接口，不覆盖已保存设置。错误与字段关联，提供 `aria-invalid`、说明和 Esc 恢复；接口保存失败同样就地提示。
- `QuestionDialog` 使用原生 `dialog.showModal()`：背景由浏览器设为 inert，Tab 焦点留在对话框内，关闭后恢复来源焦点。输入法组合期间不因 Enter / Esc 提交或关闭；每次问题使用独立 key，避免连续弹窗沿用答案。背景菜单命令与关闭窗口请求也受待答状态约束。

### 性能验收状态

实现已提供开发环境可选采样：在 DevTools 设置 `window.__workspaceMotionDebug = { enabled: true, samples: [] }`，通过真实界面完成侧栏与导航切换后读取 `samples`。记录包含布局提交耗时 `commitMs`、端点准备耗时 `setupMs`、总耗时 `duration`、首帧间隔 `firstFrameMs` 与动画帧间隔；最多保留 60 条，不含文档内容或文件路径。

`geometryReads` 只统计动效钩子调用几何读取 API 的次数，不能充当 Chromium Layout 次数或掉帧统计。本次 macOS 真实交互完成短文档与 60 节长文档共 16 次切换，176 个帧间隔的 P95 为 16.8ms，均无超过 25ms 的间隔。详见 [VALIDATION.md](VALIDATION.md)。尚未记录 Chromium Layout 事件轨迹；快速反向切换和系统减少动态效果仅做代码路径检查，不能据此声称已完成实机性能验收。

## 基础视觉规范

## 层级与尺寸

- 正文是主区域，标签负责文档切换，工具栏负责当前编辑，左侧栏负责项目/文件定位。右侧文档导航默认显示按标题层级组织的“目录”；“内容块”另列 Mark，提供移动、复制入口。
- 当前文件使用中性底色；当前 Mark 使用浅强调底和 2 px 侧标。项目名称只在项目入口完整呈现，树内入口显示“根目录”；新建文件夹与树视图切换同行。
- UI 使用系统字体：macOS 优先系统字体与苹方，Windows 回退 Segoe UI / Microsoft YaHei UI，基础字号 13 px。标签与工具 12 px，辅助状态 11 px；10 px 仅用于紧凑的类型标记等辅助信息。正文字体、字号、行距仍服从用户设置和 Mark 覆盖。
- 默认正文为 16 px、1.8 行距、780 px 内容宽度。rich 与阅读预览共享排版：H1 2.15 em，H2 1.5 em，H3 1.2 em；普通标题 650 字重，H1 700；段后距 .95 em。代码与公式保持各自的字体和布局规则。

| 项目 | 当前尺寸 |
| --- | --- |
| 原生标题栏 / 文档栏 / 工具栏 | 40 / 44 / 44 px |
| 状态栏 | 28 px |
| 侧栏 | 240 px；窗口不超过 1020 px 时为 212 px |
| 文件 / Mark 行 | 最小 32 / 27 px；树层级缩进 16 px |
| 控件 | 常规 32 px；工具栏紧凑控件 28–30 px |
| 常用间距 / 圆角 | 间距以 4/8 px 为基准，组间 12/16/24 px；基础圆角 7 px，紧凑控件 4–6 px |

正文横向留白为 20–48 px，顶部为 32–56 px，随窗口变化；对照模式收紧到横向 24 px、顶部 32 px。富文本编辑区横向至少 36 px，容纳页边块操作入口，避免侵入列表序号或引用边线。内容按最大宽度居中，长代码和表格在自身容器滚动。长文件名省略但保留完整 title，不能挤掉保存和窗口控制。

## 色彩 token

`--bg` 为正文，`--shell` 为控件底，`--sidebar` 为导航；`--surface-raised` 用于浮层。`--text`、`--muted`、`--subtle` 区分正文、辅助和细节；`--line` 与 `--outline` 区分分隔线和控件边界。强调、悬停、焦点、选择分别使用 `--accent`、`--hover`、`--focus`、`--selection`，不要互相代替。

标签与布局选中态共用 `--selected-surface` / `--selected-line`：浅色以少量白色控件凸显当前状态，深色沿用正文底色与柔和边框；设置字段共用控件底色。纯白仅用于小面积交互控件，正文仍保持灰白或淡蓝灰。

| 模式 | 正文背景 | 侧栏背景 | 正文字色 | 强调色 / 强调底 |
| --- | --- | --- | --- | --- |
| Markdown 日间 | #f5f6f3 | #ecefea | #242825 | #365f55 / #e1eae3 |
| Markdown 夜间 | #222423 | #1b1e1c | #e8ebe8 | #b0d1c1 / #2e4036 |
| Formula 日间 | #f2f5f8 | #e4ebf2 | #263447 | #2d6695 / #dae7f2 |
| Formula 夜间 | #171f2a | #141d29 | #dfebf5 | #98cbed / #263e55 |

Markdown 使用近中性灰白，墨绿集中在选中与焦点；Formula 使用冷蓝灰。日间正文、侧栏、浮层和代码底色统一降低少量亮度，避免大面积纯白；文字保持深色，细节文字略加深以维持对比度，不使用整页滤镜或透明度。标题栏、侧栏与原生窗口背景随内容模式及明暗主题同步；Windows caption 区同步使用对应底色。macOS 左上保留原生红黄绿按钮，侧栏开关位于其右侧，收起侧栏后仍留足安全区域。阴影只用于浮层和轻微控件层次；分区主要依靠留白、底色和细线。警告/危险色保留明确语义，保存状态同时提供文字，不能只靠颜色识别。

## 渐进收纳与反馈

工具栏断点按主内容区域宽度计算：不超过 1100 px 时查找入口收为图标，输入框始终在独立查找行；960 px 时上/下标等进入“更多排版”；880 px 时布局改为图标；800 px 时继续收纳下划线、删除线，保留加粗/斜体；580 px 时格式按钮统一进入菜单。入口名称、快捷键和处理逻辑保持。Formula 隐藏本就不可用的 Markdown 格式按钮。

普通状态过渡使用 `--motion: 140ms cubic-bezier(.2,.7,.2,1)`；主题配色过渡 160 ms。侧栏与标题栏使用 190 ms FLIP，布局一次提交，动画帧仅改变 `translate3d` / `opacity`，不对宽度逐帧过渡。内容块转换菜单使用 140 ms 淡入；右侧面板使用 180 ms 入场。避免持续动画和滚动接管。`prefers-reduced-motion: reduce` 关闭动画、过渡和平滑滚动。键盘焦点保留清晰外框；hover 不能成为操作入口唯一可见的条件。

内容块悬停或选中后显示六点格式入口；右键和 Shift+F10 打开同一“转换为”菜单，目标块有轻微底色提示。菜单支持方向键、Esc、Tab 和窗口边缘避让。保留内容与层级优先；复杂嵌套块不提供会扁平化内容的正文/标题转换，并说明原因。

## 既有自检记录与停止条件

1. **第一轮：结构与规则收敛。** 核对标题栏、文档栏、工具栏和正文关系；统一 rich/preview 排版，区分文件/Mark 选中状态，设置渐进收纳与短动效。用不同窗口尺寸、两种内容模式及明暗主题检查长标题、表格、公式和菜单。
2. **第二轮：实际截图复审。** 检查 Markdown 1440×1000、920×620、夜间 1100×760，以及 Geek 1440×1000。发现侧栏项目名称重复、夜间底色过绿、Geek 留有整排不可用按钮，随后压缩侧栏标题、降低夜间底色偏色、隐藏 Geek 无效格式组。后续验收仍针对真实渲染结果。

停止条件是：**没有明显层级、可读性、裁切或状态反馈问题，且功能与性能检查通过。** 不为主观“更精致”无限调整，不用几何检查替代真实截图，也不用截图替代交互检查。最终检查结果和性能数字统一记录在 [VALIDATION.md](VALIDATION.md)，本文件不推测成绩。

## 功能边界与参考依据

内容块格式转换沿用既有 Mark 身份、局部样式与共享撤销机制；未编辑块按原文保留。草稿、保存/Git、项目权限和窗口关闭流程沿用现有实现。继续保留原生窗口拖动/缩放/caption、快捷键和菜单。没有增加 Word、Excel、PDF 或其他编辑器，也没有引入新的运行依赖。

官方标准用于建立检查角度，**不代表参赛认证，也不保证获奖**：

- [Awwwards Evaluation System](https://www.awwwards.com/about-evaluation/)：设计 40%、可用性 30%、创意 20%、内容 10%；本应用据此检查一致性、操作效率、Mark 交互辨识度与文案准确性。
- [Webby Judging Criteria](https://www.webbyawards.com/judging-criteria/)：参考 Apps, Software & Immersive 中的内容、结构导航、视觉、功能、交互、执行、创新及整体体验；视觉质量须服务实际使用，不能只检查首页或静态外观。
- [FWA 官方宗旨](https://thefwa.com/about/about-fwa/)：参考前沿创意、创新与进步的方向；本应用把辨识度放在内容定位和编辑反馈，不据此追加展示性特效。未使用未经官方确认的分项评分比例。
