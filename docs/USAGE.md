# MarkFlow 使用指南

公式与完整 LaTeX 文档统一从 **顶部标签栏 ＋ → Fomula** 打开，使用工具栏的“公式片段 / LaTeX 文档”切换。文档模式支持模板创建、多文件源码编辑、页面设置、实际 PDF 跨页预览、手动双向定位与导出。详见[论文工作区](LATEX-WORKSPACE.md)。

[返回首页](../README.md) · [开发与调试](DEVELOPMENT.md) · [验证记录](VALIDATION.md)

MarkFlow 以本地 UTF-8 文件为内容来源。文件保存、本地 Git 版本和远端同步是三个独立步骤；未连接 GitHub 也可以编辑、预览和保存。

## 第一次使用

1. 启动后直接在新文档中输入内容；左侧“项目”旁的加号提供新建项目、打开本地项目、从链接获取三个入口。
2. 按 **Ctrl+S**，选择保存位置与文件名，例如 `说明.md`。取消对话框会保留内容。
3. 在“实时预览 / 源码 / 对照”之间切换，选择适合当前工作的视图。
4. 点击顶部标签栏的加号，选择 **Markdown** 或 **Fomula**；也可从左侧文件树打开已有文档。快捷键新建默认创建 Markdown。
5. 如需版本记录，再到“Git 与同步”中明确启用 Git。单纯打开文件夹不会初始化仓库。

## 生成 Word 报告 / PPT 演示

Markdown 第二栏的 **生成**、标签栏 **+ → 生成 Word / PPT…**、原生“文件”菜单均可打开生成面板。

- **当前文档**：使用打开面板时的 Markdown 编辑快照，包含尚未保存的内容。打开面板期间暂停自动版本保存；关闭后恢复原规则。Fomula 不能作为生成来源。
- **内置示例**：使用同一份共享资料及配套呈现，生成报告或四页演示，可先用它试用完整流程。
- **选择本地资料**：支持 Markdown 和 MarkFlow JSON。选择来源不会切换项目或改写当前文档。

选择 Word 或 PPT 后点击生成，在系统保存对话框中选择输出位置。取消保留原编辑；错误不覆盖已有输出。成功页可打开生成文件或定位所在文件夹。

“高级设置”可指定呈现 JSON、图片素材文件夹和字体文件。当前已保存文档的相对图片按所属项目授权解析；未命名文档及独立选择的资料，需要明确选择图片所在的素材文件夹。默认字体为本机 `Microsoft YaHei`，不存在时会提示选择，不会静默替换。界面布局、编辑器默认字号不等于 Office 呈现主题。

生成器首版支持标题、段落、扁平列表、简单表格、PNG/JPEG 图片和受支持的文字格式。公式、代码、复杂嵌套等会返回明确诊断；支持定位的当前文档错误可直接跳回对应 Mark。详细边界见[编译语言](compiler/LANGUAGE.md)。这不是 Word/PPT 可视化编辑器，也不支持导入或保真往返。

## 项目、草稿与保存

每个项目入口对应这台电脑上的一个本地工作副本，可以关联 GitHub，或交给坚果云等客户端同步。日常编辑始终在本地文件夹进行。没有历史项目时直接进入可编辑的新文档；有标签会话时恢复标签，没有标签但有历史项目时提供“继续上次项目”和“新建文档”。

- **新建项目**：输入名称，选择存放位置，创建一个新文件夹。已有同名文件夹不会被覆盖，也不会自动启用 Git。
- **打开本地项目**：选择已有文件夹，直接使用原位置。已有仓库应选择仓库根目录。
- **从链接获取**：输入 GitHub 仓库根地址。先核对已登记副本的真实仓库来源，列出路径、当前分支和可用性；可直接复用，或明确创建另一份副本。创建副本需要选择本地存放位置；失败的下载保留在提示的位置，原有目录不会被覆盖。

同一仓库的不同本地副本分别显示，打开不会静默切换分支。已登记副本落后于远端时，使用“检查更新”和“更新到本地”，不重新克隆覆盖。项目菜单可重新定位移动后的文件夹，迁移该设备上的草稿、归档及阅读位置，包括 LaTeX 草稿和主文件/引擎配置；目标存在不同恢复数据时停止迁移，旧数据保留。

LaTeX 使用同一份项目列表。新建模板、打开文件夹、导入 ZIP、从 Mark 生成或另存独立 LaTeX 后，项目都会加入左侧系统项目栏；文件树、归档、拖动、右键操作和“Git 与同步”共用，不再单独登记论文项目。

移除项目只取消列表登记，不删除本地文件或远端仓库。存在未保存内容时先按提示保护草稿。坚果云等云盘目前使用**已同步到本机的文件夹**，在项目菜单标记由云盘客户端管理；MarkFlow 只确认本地保存，不显示未经验证的云端完成状态，也不同时执行 Git 远端操作。普通分享链接和 WebDAV 连接尚未接入。

新建 Markdown 或公式片段时先创建独立草稿，不要求立即选文件夹；完整 LaTeX 模板在创建时选择项目位置。独立草稿的首次保存对话框默认定位到当前项目，也可以选择其他位置。草稿以顶部标签显示，内容先保留在本机设备数据目录；它不会自动弹出保存对话框、提交 Git，或从之前的项目解析相对图片。

首次保存采用新文件写入：重名时保留已有文件并要求更换名称。该安全写入方式需要支持硬链接的本地文件系统，历史 Windows 验证覆盖 NTFS；不支持时会提示换保存位置，草稿继续保留。保存到项目后，文档沿用常规保存、版本和同步规则。

切换标签会先保护草稿。关闭未保存标签时，可以保存、保留草稿或取消；**Ctrl+Shift+T** 可重新打开最近关闭的标签。保存过程中继续输入的内容会保持为未保存修改，不会被较早的保存快照覆盖。

确认或命名对话框打开时，背景暂时不可操作，Tab / Shift+Tab 只在对话框内移动焦点。Enter 执行当前按钮或提交输入，Esc 取消；输入法组合期间不会因 Enter / Esc 提交或关闭。关闭后恢复触发位置的焦点。对话框打开期间，保存、切换文档等后台菜单命令暂停响应。

草稿通常在输入停止约 **250 ms** 后写入设备数据目录，突然断电仍可能损失这段尚未持久化的输入。设备设置、恢复草稿与归档索引不在文档 Git 仓库中，也不会随仓库自动同步到另一台电脑。

## 编辑视图与语法

| 文档类型 | 视图 | 用途 |
| --- | --- | --- |
| Markdown | 实时预览、源码、对照 | 直接编辑排版后的内容，或编辑 Markdown 正文 |
| Fomula · 公式片段 | 对照、源码 | 输入 LaTeX 数学片段，同时查看公式渲染 |
| Fomula · LaTeX 文档 | 对照、源码 | 编辑完整 TeX 项目，编译后查看实际分页 PDF |

Markdown 默认使用实时预览，当前 Mark 不显示 Markdown 标记。源码和对照使用 CodeMirror；已识别的 Oops 身份元数据由适配器维护，不放入源码编辑区。切换视图保留正文和撤销历史。Fomula 默认对照：公式片段接收 `\frac{a}{b}` 等数学内容；LaTeX 文档模式编译完整项目，右侧 PDF 可独立滚动查看跨页内容。

Markdown 与 Fomula 是独立文档类型。顶部类型标识用于说明当前文档，不把现有正文原地切换成另一种格式。需要另一类型时，从加号另建文档；重命名不能把 Markdown 改成 `.tex`，也不能把 Fomula 改成 Markdown。打开已保存的完整 TeX 文档时会转入 Fomula 的文档工作区。

支持标题、段落、引用、列表、围栏/缩进代码、分隔线、链接、相对图片、表格、任务列表、删除线及自动链接；数学公式由 KaTeX 渲染。解析基准为 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/) 和 [GFM 0.29-gfm](https://github.github.com/gfm/)，使用 remark-parse 11 / remark-gfm 4。解析器版本号不是 Markdown 标准版本号。

加粗、斜体等文字格式可从工具栏操作；下划线、上标、下标、荧光笔保存为安全的 `u` / `sup` / `sub` / `mark` 标签，它们不是 CommonMark 的独立语法。任意原始 HTML 和脚本不会执行。预览仅自动加载项目内的相对图片；外部链接需明确点击后交给系统打开。

富文本编辑使用 Tiptap / ProseMirror：未编辑 Mark 的原文、引用定义及间隔按原文保留，仅对修改过的 Mark 生成 Markdown。暂不支持编辑的特殊结构显示为受保护 Mark，可切换源码修改。标准解析覆盖范围与富文本可编辑范围不同，不能据此认为所有 Markdown 方言都支持所见即所得编辑。

## 主题与显示

顶部主题按钮和「设置 → 外观 → 主题」都可选择「跟随本机」「浅色」「深色」。新安装默认跟随本机，已有的浅色或深色选择保持不变。跟随本机时，系统明暗变化会同步到编辑器、预览和窗口外壳；手动选择明暗则不受系统切换影响。Markdown 和 Fomula 分别保留自己的中性／蓝灰配色。

主题菜单支持上下方向键、Enter、Esc、Tab 和 Shift+Tab。设置分为外观、阅读、版本记录；打开设置时暂时收起文档导航，关闭后恢复之前的固定状态。窄窗口中的设置浮在右侧，避免继续挤压正文。

设置与工具栏的下拉选择使用统一的箭头和文字留白，保留系统选择列表及键盘操作。左侧分隔线贯通标题栏与项目栏；收起侧栏时一起退出，保留 macOS 原生窗口按钮的安全区域。

## Mark 与局部排版

**Mark 是文档中的内容单元**，例如一段文字、一个标题或一个列表项。它们仍保存在同一份 Markdown 文件中，不会拆成多个磁盘文件。当前身份范围是顶层语义节点与顶层列表项，尚非完整嵌套 AST。

文档目录位于正文右侧，只列 H1–H6 标题。默认保留窄入口；至少有两个标题时显示刻度，悬停可临时展开。只有零个或一个标题时默认只显示入口，点击仍可打开。面板支持固定、搜索和层级折叠；编辑时跟随当前标题，阅读滚动时跟随可见章节，源码视图跟随光标。

正文主区不足 600 px，或对照视图主区不足 900 px 时，固定目录自动改为浮层，避免继续挤压编辑区。原固定偏好仍保留；放宽窗口后恢复并排显示。关闭窄窗口中的临时浮层不会清除固定偏好，点击“取消固定”才会更改偏好。

目录的“更多”入口提供次级“内容块”检查器，列出当前文档的 Mark；普通段落和列表不充当目录标题。工具栏调整当前 Mark 的字体、字号；“恢复 Mark 默认样式”清除局部覆盖，未手动设置的 Mark 继承设置面板的默认字体、默认字号。Fomula 使用设备上的默认排版，不显示 Markdown 目录和块格式工具。

普通段落按 **Enter** 新建 Mark，**Shift+Enter** 在当前 Mark 内换行。新 Mark 使用默认样式；列表回车继续下一项，空列表项回车退出列表。代码、公式和表格内部按语法保留换行，完整结构 Mark 末尾回车新建下一 Mark。

在段首单独输入 **/** 打开标记建议，继续输入字母筛选，例如 Markdown 中的 `/h2`、`/list`、`/todo`、`/table`。输入独立的 **\\** 可选择数学命令，例如 `\frac`、`\sqrt`；Fomula 的公式与文档编辑器同时支持 `/` 和 `\`，完整文档另提供章节、列表、引用等命令。每项显示中文用途和插入示例。**↑ / ↓** 选择，**Tab** 插入，**Esc** 关闭；网址、普通分数、连续双反斜线和已有命令的中间位置不会激活。输入法组合过程中不接管这些按键，只读文档不修改内容。

候选依次按**完整匹配、前缀匹配、包含匹配**排序；同类匹配再按已确认接受的次数、最近使用时间排序。只在本机保存有限数量的命令编号、使用次数和时间，不记录正文，也不会上传这些使用记录。

左侧底部 **设置 → 自动补全** 可分别配置 **Markdown、Fomula · 公式片段、Fomula · LaTeX 文档**。可开关补全或单个触发符、选择前缀/包含匹配和常用/字母排序、禁用内置标记、添加自己的触发词与多行内容。同名自定义规则覆盖该页面类型的内置规则；每类最多 32 条，每条最多 4,096 字符。频次也按页面类型独立记录。保存后立即生效，保留正文、光标和撤销记录，重启仍保留规则。

没有补全建议时，**Tab** 缩进、**Shift+Tab** 反缩进，选择文字后操作不会覆盖所选文字。源码每级为两个空格；Markdown 排版视图的列表使用真正的列表嵌套，普通段落使用可随 Markdown 保存的三个 en 空格作为段首排版空白，16 px 字号下约为 24 px。普通段落的这种缩进不是父子容器层级，也不是 Notion 的官方尺寸。补全和缩进均可撤销。

右键“内容块”检查器中的条目可选择“上移 Mark”“下移 Mark”“复制 Mark”，也可用 **Shift+F10** 打开菜单。移动保留身份；复制生成新身份并保留局部样式。操作可撤销；若目标位置会改变 Markdown 结构，则拒绝该操作。

在正文中悬停或选中 Mark，点击左侧六点按钮，或右键 / **Shift+F10** 打开“转换为”：支持正文、H1/H2/H3、无序列表、有序列表、待办事项、引用和代码块。源码模式也可右键转换所在 Mark。菜单支持方向键、Esc 与 Tab。转换保留 Mark 身份、局部样式和撤销历史；含多个子块的嵌套结构禁用会压平层级的正文/标题选项。表格、公式和受保护结构不提供格式转换。转为代码时保留链接、图片、公式等原有 Markdown 表达。

所有活跃 Mark 都有身份，身份与局部样式保存在 `.md` 尾部的 Oops 注释元数据中，随草稿、撤销、保存、Git、移动和复制保留：

- 首次打开普通 Markdown 时，身份先在当前会话内补齐，不自动改磁盘，也不会仅因此显示未保存。
- **主动保存会将身份元数据写入文件，即使正文没有修改。** 如果从未保存或产生草稿就关闭，下次打开可以重新分配身份。
- 修改局部字体、字号不重写正文，但会改变元数据，因此需要保存，也可以进入版本记录。
- 其他 Markdown 软件通常只显示正文，不解释 Oops 的局部样式。外部工具删除专用注释，会丢失已有身份与样式，再打开时重新分配身份。
- 外部修改使对应关系不确定时，不猜测身份或样式。删除后仅在 registry 中保留退役 ID，被删正文仍可通过撤销历史恢复。

字体列表包含系统默认及六款候选字体，未安装的字体会标注“未安装”。没有单独字重列表，加粗和斜体是文字格式；代码默认等宽显示。字号单位为 CSS px。默认字体与字号是设备阅读偏好，局部覆盖才随文档携带。实现与后续页面边界见 [Mark 引擎架构](OOPS-ENGINE-ARCHITECTURE.md)。

## 标签、搜索与快捷键

标签位于文件路径上方，可以点击切换、拖动排序、中键或 × 关闭；右键菜单提供固定、关闭其他、关闭右侧和重新打开关闭的标签。每个标签保留独立的编辑缓冲、撤销历史与视图布局。

标签菜单与“更多排版”支持方向键、Home / End、Enter、Esc 和 Tab。Esc 先关闭当前菜单并恢复触发位置的焦点，不连带关闭文档导航；目录搜索框中有关键词时，Esc 先清空关键词。窗口或编辑区尺寸变化时，相关菜单会关闭，避免留在错误位置。

点击工具栏“搜索”或按 **Ctrl+F**，在工具栏下方打开独立查找行；输入关键词后显示匹配计数，并可前后跳转。切换文档或编辑布局时，清空查询、匹配标记和计数；关闭查找后焦点回到编辑器。

| 快捷键 | 操作 |
| --- | --- |
| Ctrl+T / Ctrl+N | 新建 Markdown 文档 |
| Ctrl+S | 保存当前快照，满足条件时记录本地版本 |
| Ctrl+W | 关闭当前标签 |
| Ctrl+Shift+T | 重新打开最近关闭的标签 |
| Ctrl+Tab / Ctrl+Shift+Tab | 切换到下一 / 上一标签 |
| Ctrl+1…8 / Ctrl+9 | 选择对应位置 / 最后一个标签 |
| Ctrl+F | 打开并聚焦页内查找行 |
| Enter / Shift+Enter（搜索中） | 下一个 / 上一个匹配 |
| Escape（搜索中） | 退出搜索 |
| Alt+1 / Alt+2 / Alt+3 | 实时预览 / 源码 / 对照；Fomula 的 Alt+1 映射为对照 |
| Shift+F10 | 打开当前文件或 Mark 的上下文菜单 |
| Alt+F4 | 关闭窗口 |

三种编辑页面只有一条应用栏：显示项目、文件名和类型，操作固定按 **打开文件 → 主题 → 版本历史 → 保存** 排列。新建类型从标签栏加号选择。第二栏提供当前引擎的排版、页内搜索、布局或编译命令；LaTeX 的 **编译环境** 和 **编译选项** 也在第二栏。窗口变窄时功能按钮可以收纳或换行；“更多排版”仍提供全部七种格式。Fomula 使用 LaTeX 数学命令。macOS 常用快捷键使用 Command，Windows 使用 Ctrl。

Markdown 日间使用柔和的灰绿底色，Fomula 使用冷蓝灰；夜间分别使用中性炭灰与冷蓝灰。标题栏、侧栏与窗口背景同步切换配色，保留各系统原生窗口操作。侧栏展开/收起、菜单和面板提供短动效；系统开启“减少动态效果”时关闭这些动画。

## 文件树、移动与归档

所有编辑页面使用同一侧栏。**文件树**显示文件和目录的完整层级；**文件夹树**只显示目录，选中后在下方显示该层文件。右侧文档目录独立于左侧文件树视图。LaTeX 的章节、`.bib/.cls/.sty/.bst` 等文本在论文编辑器打开，图片和 PDF 等资源仍列在树中；二进制文件不会交给 Markdown 编辑器。

文件和文件夹可以拖到同一项目的其他文件夹或根目录，目标重名、移入自身会被拒绝。右键可以重命名、归档或移到系统回收站；重命名会报告常见内部链接的影响并迁移草稿，但不自动修复链接。LaTeX 迁移包含当前未打开文件的恢复草稿；目标草稿冲突会阻止移动，文件已移动但恢复记录迁移失败时会提示并保留旧记录。仍含未保存草稿的目录会阻止删除，需先恢复保存或导出。

打开 `sections/chapter.tex` 等子文件时保留已授权的整个项目根，不把章节文件夹另登记为项目。Mark 生成稿的只读保护也作用于系统文件树：修改、添加、移动或删除生成来源需先另存独立 LaTeX；逻辑归档仍可用。

归档只隐藏工作树条目：文件路径、正文、附件与 Git 内容保持不变。左侧“归档”默认收起，展开后仍可浏览和编辑；右键“恢复到工作树”撤销归档。归档文件夹覆盖其子项，恢复其中一个文件时会恢复整个所在归档。

归档记录按项目保存在设备数据的 `archive` 目录，包含相对路径和归档时间。应用内移动、改名、删除会更新记录；外部程序移动文件不能自动跟踪，归档索引尚不跨设备同步。

## 保存、本地版本与远端同步

| 操作 | 结果 |
| --- | --- |
| 草稿保护 | 将未保存内容保留在设备数据目录，不替代文档文件 |
| Ctrl+S / 阈值保存 | 检查外部变化，再将当前内容快照写入文件 |
| 本地版本记录 | Git 已启用且状态允许时，提交选定快照 |
| 检查更新 | 获取远端状态，不更改工作文件、不上传 |
| 更新到本地 | 将远端版本快进或合并到当前本地分支，不上传 |
| 上传更改 | 将已记录的本地版本上传，不隐式合并或保存草稿 |

### 启用本地 Git

打开“Git 与同步”，填写作者姓名、邮箱，再明确点击“启用 Git 并建立基线”。如打开的是已有仓库，请选择仓库根目录；应用不把上层或嵌套仓库当作当前项目的 Git 根。

设置中的自动版本阈值默认为 **500**，可自行调整或关闭自动记录。计数针对相对版本基线的正文净变化，不是累计按键次数；身份元数据不计入阈值。一次粘贴超过阈值只记录一个快照，Ctrl+S 不创建空提交。独立未命名草稿不会触发自动保存到项目或自动提交。

阈值必须是大于 0 的整数，修改后点击右侧“保存”按钮或按 Enter 才生效，离开输入框不保存。按钮区分未修改、可保存、保存中和已保存状态。空值、0、小数等无效输入会在字段下方说明，保留原来的已保存设置；按 Esc 恢复已保存值。保存失败也在字段内提示，不弹出通用设置错误。

保存顺序为快照、外部修改检查、写盘、条件性提交。Git 失败时，已写盘的文件仍保留，界面会区分“已保存，但版本记录失败”；自动记录暂停，处理原因后手动保存可重试。没有网络不会阻止本地编辑、保存与本地提交。

### 连接 GitHub

已有远端内容时，从项目加号选择“从链接获取”，输入 GitHub HTTPS / SSH 仓库根地址。也可以在外部 Git 工具克隆后，通过“打开本地项目”选择已有副本。

已有本地仓库可以在“Git 与同步”填写远端地址和远端分支，点击“保存仓库配置”。这个操作只建立跟踪关系，不切换当前本地分支。私有仓库先通过 Git Credential Manager 授权，或配置可用的 SSH 密钥；可先在终端对该仓库执行一次 `git fetch origin`，完成浏览器授权或 SSH 主机指纹确认。

打开已连接的项目会在后台检查远端；显示最近检查时间。未检查或网络失败时会明确显示状态，本地内容仍可使用。远端领先时更新，本地领先时上传；双方都有提交时先合并并处理冲突。远端目标分支不存在时，普通上传停止；只有明确选择发布新分支才会创建它，不自动恢复被删除的远端分支。

应用不保存账号口令、token 或私钥，不把凭据写入仓库 URL。开发版调用 PATH 上的 Git；Windows 安装版携带固定 MinGit、Git Credential Manager 和 OpenSSH，来源与许可证见 [Git 运行时](GIT-RUNTIME.md)。

### 暂存与冲突

更新本地或处理合并前需处理该项目**所有打开标签**、工作区和暂存区中的变更，包括非当前标签。更新期间暂停编辑，完成后重新读取干净的文档缓存。检查更新不要求清空修改；上传只上传已有提交，未保存内容不在上传范围内。记录变更时只选择本次文件，附件可随当前文档提交；改名需选择旧、新两条路径。其他工具已暂存当前文件时会暂停版本记录，其他已暂存文件保持原样。

同步不会强推。文本、二进制、删除/修改冲突可逐文件选择本地或远端，再完成合并；也可中止合并后交给外部 Git 工具细化处理。没有共同历史的两套仓库会拒绝自动合并，应先克隆到新目录，再有选择地复制文档。

精确快照提交使用 Git plumbing，不运行 commit hooks，也不自动签名。已有仓库的特殊合并状态、当前文件暂存和锁不会被自动清除。

### 外部程序同时修改文件

检测到磁盘与当前编辑同时变化时，两端内容都保留，暂停直接覆盖。可先导出磁盘副本后保留编辑，或备份编辑后载入磁盘，再决定保存哪一份。复杂字符差异在 Worker 中精确计算；超时会提示手动保存，不用近似值代替计数。

## 当前限制

- 文本编码只支持 UTF-8。已有文件保存时保留 BOM 与换行风格；混合换行在编辑后按首个换行风格统一。只读打开不改字节；普通 Markdown 首次主动保存会写入前述 Mark 元数据。
- Windows 历史验收与本轮 macOS 开发版检查分别记录在 [验证记录](VALIDATION.md)；macOS / Linux 安装包尚未验证。开发接续步骤见 [开发指南](DEVELOPMENT.md)。
- 输入法组合事件有保护，真实中文输入法候选窗仍需人工验收。真实 GitHub 公私有账号授权及跨设备联网往返也需要使用自己的仓库验收；已有自动同步测试使用本机两份工作副本和裸仓库。
- 尚无跨文件全文搜索、PDF 导出、完整 TeX 编译、AI、Notion 数据库、斜杠菜单或跨页 Mark 引用。Word / PPT 已支持上述生成流程；Note / Array / Stage / PDF 可视化编辑器尚未接入。

已执行测试与待验收事项分别记录在 [验证记录](VALIDATION.md) 和 [开发清单](../OopsMD-TODO.md)。
