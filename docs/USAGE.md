# OopsMD 使用指南

[返回首页](../README.md) · [开发与调试](DEVELOPMENT.md) · [验证记录](VALIDATION.md)

OopsMD 以本地 UTF-8 文件为内容来源。文件保存、本地 Git 版本和远端同步是三个独立步骤；未连接 GitHub 也可以编辑、预览和保存。

## 第一次使用

1. 启动后直接在新文档中输入内容；也可以点击左侧“项目”旁的加号，打开已有文件夹。
2. 按 **Ctrl+S**，选择保存位置与文件名，例如 `说明.md`。取消对话框会保留内容。
3. 在“实时预览 / 源码 / 对照”之间切换，选择适合当前工作的视图。
4. 从顶部标签栏的加号继续新建，或从左侧文件树打开其他文档。
5. 如需版本记录，再到“Git 与同步”中明确启用 Git。单纯打开文件夹不会初始化仓库。

## 项目、草稿与保存

一个项目对应一个本地文件夹，左侧项目列表用于切换。没有历史项目时直接进入可编辑的新文档；有标签会话时恢复标签，没有标签但有历史项目时提供“继续上次项目”和“新建文档”。

“新建文档”始终先创建独立草稿，不要求立即选文件夹。首次保存对话框默认定位到当前项目，也可以选择其他位置。草稿以顶部标签显示，内容先保留在本机设备数据目录；它不会自动弹出保存对话框、提交 Git，或从之前的项目解析相对图片。

首次保存采用新文件写入：重名时保留已有文件并要求更换名称。该安全写入方式需要支持硬链接的本地文件系统，本机 NTFS 已验证；不支持时会提示换保存位置，草稿继续保留。保存到项目后，文档沿用常规保存、版本和同步规则。

切换标签会先保护草稿。关闭未保存标签时，可以保存、保留草稿或取消；**Ctrl+Shift+T** 可重新打开最近关闭的标签。保存过程中继续输入的内容会保持为未保存修改，不会被较早的保存快照覆盖。

草稿通常在输入停止约 **250 ms** 后写入设备数据目录，突然断电仍可能损失这段尚未持久化的输入。设备设置、恢复草稿与归档索引不在文档 Git 仓库中，也不会随仓库自动同步到另一台电脑。

## 编辑视图与语法

| 模式 | 视图 | 用途 |
| --- | --- | --- |
| Markdown | 实时预览、源码、对照 | 直接编辑排版后的内容，或编辑 Markdown 正文 |
| Geek | 对照、源码 | 输入 LaTeX 数学片段，同时查看公式渲染 |

Markdown 默认使用实时预览，当前 Mark 不显示 Markdown 标记。源码和对照使用 CodeMirror；已识别的 Oops 身份元数据由适配器维护，不放入源码编辑区。切换视图保留正文和撤销历史。Geek 默认对照，接收 `\frac{a}{b}` 等数学片段，不编译完整 TeX 文档。

支持标题、段落、引用、列表、围栏/缩进代码、分隔线、链接、相对图片、表格、任务列表、删除线及自动链接；数学公式由 KaTeX 渲染。解析基准为 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/) 和 [GFM 0.29-gfm](https://github.github.com/gfm/)，使用 remark-parse 11 / remark-gfm 4。解析器版本号不是 Markdown 标准版本号。

加粗、斜体等文字格式可从工具栏操作；下划线、上标、下标、荧光笔保存为安全的 `u` / `sup` / `sub` / `mark` 标签，它们不是 CommonMark 的独立语法。任意原始 HTML 和脚本不会执行。预览仅自动加载项目内的相对图片；外部链接需明确点击后交给系统打开。

富文本编辑使用 Tiptap / ProseMirror：未编辑 Mark 的原文、引用定义及间隔按原文保留，仅对修改过的 Mark 生成 Markdown。暂不支持编辑的特殊结构显示为受保护 Mark，可切换源码修改。标准解析覆盖范围与富文本可编辑范围不同，不能据此认为所有 Markdown 方言都支持所见即所得编辑。

## Mark 与局部排版

**Mark 是文档中的内容单元**，例如一段文字、一个标题或一个列表项。它们仍保存在同一份 Markdown 文件中，不会拆成多个磁盘文件。当前身份范围是顶层语义节点与顶层列表项，尚非完整嵌套 AST。

文件树在当前文件节点下显示 Mark；草稿和文件夹树模式使用独立大纲。点击大纲定位后，可以直接编辑，或调整整个 Mark 的字体、字号。工具栏中的“恢复 Mark 默认样式”清除局部字体及字号覆盖；未手动设置的 Mark 继承设置面板的默认字体、默认字号。Geek 使用设备上的默认排版。

普通段落按 **Enter** 新建 Mark，**Shift+Enter** 在当前 Mark 内换行。新 Mark 使用默认样式；列表回车继续下一项，空列表项回车退出列表。代码、公式和表格内部按语法保留换行，完整结构 Mark 末尾回车新建下一 Mark。

右键大纲条目可选择“上移 Mark”“下移 Mark”“复制 Mark”，也可用 **Shift+F10** 打开菜单。移动保留身份；复制生成新身份并保留局部样式。操作可撤销；若目标位置会改变 Markdown 结构，则拒绝该操作。

所有活跃 Mark 都有身份，身份与局部样式保存在 `.md` 尾部的 Oops 注释元数据中，随草稿、撤销、保存、Git、移动和复制保留：

- 首次打开普通 Markdown 时，身份先在当前会话内补齐，不自动改磁盘，也不会仅因此显示未保存。
- **主动保存会将身份元数据写入文件，即使正文没有修改。** 如果从未保存或产生草稿就关闭，下次打开可以重新分配身份。
- 修改局部字体、字号不重写正文，但会改变元数据，因此需要保存，也可以进入版本记录。
- 其他 Markdown 软件通常只显示正文，不解释 Oops 的局部样式。外部工具删除专用注释，会丢失已有身份与样式，再打开时重新分配身份。
- 外部修改使对应关系不确定时，不猜测身份或样式。删除后仅在 registry 中保留退役 ID，被删正文仍可通过撤销历史恢复。

字体列表包含系统默认及六款候选字体，未安装的字体会标注“未安装”。没有单独字重列表，加粗和斜体是文字格式；代码默认等宽显示。字号单位为 CSS px。默认字体与字号是设备阅读偏好，局部覆盖才随文档携带。实现与后续页面边界见 [Mark 引擎架构](OOPS-ENGINE-ARCHITECTURE.md)。

## 标签、搜索与快捷键

标签位于文件路径上方，可以点击切换、拖动排序、中键或 × 关闭；右键菜单提供固定、关闭其他、关闭右侧和重新打开关闭的标签。每个标签保留独立的编辑缓冲、撤销历史与视图布局。

| 快捷键 | 操作 |
| --- | --- |
| Ctrl+T / Ctrl+N | 新建文档 |
| Ctrl+S | 保存当前快照，满足条件时记录本地版本 |
| Ctrl+W | 关闭当前标签 |
| Ctrl+Shift+T | 重新打开最近关闭的标签 |
| Ctrl+Tab / Ctrl+Shift+Tab | 切换到下一 / 上一标签 |
| Ctrl+1…8 / Ctrl+9 | 选择对应位置 / 最后一个标签 |
| Ctrl+F | 聚焦页内搜索 |
| Enter / Shift+Enter（搜索中） | 下一个 / 上一个匹配 |
| Escape（搜索中） | 退出搜索 |
| Alt+1 / Alt+2 / Alt+3 | 实时预览 / 源码 / 对照；Geek 的 Alt+1 映射为对照 |
| Shift+F10 | 打开当前文件或 Mark 的上下文菜单 |
| Alt+F4 | 关闭窗口 |

工具栏从左到右依次为模式、字体字号、文字格式、页内搜索和布局。窗口变窄时按可用空间逐步收纳；“更多排版”仍提供全部七种格式。Geek 隐藏不可用的 Markdown 格式工具，使用 LaTeX 命令。

Markdown 日间使用柔和的灰绿底色，Geek 使用冷蓝灰；夜间分别使用中性炭灰与冷蓝灰。标题栏与标签区融合，保留 Windows 的窗口拖动、最小化、最大化和关闭操作。

## 文件树、移动与归档

**文件树**显示文件和目录的完整层级；**文件夹树**只显示目录，选中后在下方显示该层文件。两种视图都能访问当前文档大纲。

文件和文件夹可以拖到同一项目的其他文件夹或根目录，目标重名、移入自身会被拒绝。右键可以重命名、归档或移到系统回收站；重命名会报告常见内部链接的影响并迁移草稿，但不自动修复链接。仍含未保存草稿的目录会阻止删除，需先恢复保存或导出。

归档只隐藏工作树条目：文件路径、正文、附件与 Git 内容保持不变。左侧“归档”默认收起，展开后仍可浏览和编辑；右键“恢复到工作树”撤销归档。归档文件夹覆盖其子项，恢复其中一个文件时会恢复整个所在归档。

归档记录按项目保存在设备数据的 `archive` 目录，包含相对路径和归档时间。应用内移动、改名、删除会更新记录；外部程序移动文件不能自动跟踪，归档索引尚不跨设备同步。

## 保存、本地版本与远端同步

| 操作 | 结果 |
| --- | --- |
| 草稿保护 | 将未保存内容保留在设备数据目录，不替代文档文件 |
| Ctrl+S / 阈值保存 | 检查外部变化，再将当前内容快照写入文件 |
| 本地版本记录 | Git 已启用且状态允许时，提交选定快照 |
| 手动同步 | fetch、合并，再 push 到已配置远端 |

### 启用本地 Git

打开“Git 与同步”，填写作者姓名、邮箱，再明确点击“启用 Git 并建立基线”。如打开的是已有仓库，请选择仓库根目录；应用不把上层或嵌套仓库当作当前项目的 Git 根。

设置中的自动版本阈值默认为 **500**，可自行调整或关闭自动记录。计数针对相对版本基线的正文净变化，不是累计按键次数；身份元数据不计入阈值。一次粘贴超过阈值只记录一个快照，Ctrl+S 不创建空提交。独立未命名草稿不会触发自动保存到项目或自动提交。

保存顺序为快照、外部修改检查、写盘、条件性提交。Git 失败时，已写盘的文件仍保留，界面会区分“已保存，但版本记录失败”；自动记录暂停，处理原因后手动保存可重试。没有网络不会阻止本地编辑、保存与本地提交。

### 连接 GitHub

已有远端内容时，先克隆，再在 OopsMD 打开仓库根目录：

```powershell
git clone https://github.com/你的账号/你的仓库.git "D:\OopsMD-notes"
```

在“Git 与同步”填写 GitHub HTTPS / SSH URL 和分支，点击“保存仓库配置”，再手动同步。私有仓库先通过 Git Credential Manager 授权，或配置可用的 SSH 密钥；可先在终端对该仓库执行一次 `git fetch origin`，完成浏览器授权或 SSH 主机指纹确认。

应用不保存账号口令、token 或私钥，不把凭据写入仓库 URL。开发版调用 PATH 上的 Git；Windows 安装版携带固定 MinGit、Git Credential Manager 和 OpenSSH，来源与许可证见 [Git 运行时](GIT-RUNTIME.md)。

### 暂存与冲突

同步前需处理编辑器、工作区和暂存区中的变更。记录变更时只选择本次文件，附件可随当前文档提交；改名需选择旧、新两条路径。其他工具已暂存当前文件时会暂停版本记录，其他已暂存文件保持原样。

同步不会强推。文本、二进制、删除/修改冲突可逐文件选择本地或远端，再完成合并；也可中止合并后交给外部 Git 工具细化处理。没有共同历史的两套仓库会拒绝自动合并，应先克隆到新目录，再有选择地复制文档。

精确快照提交使用 Git plumbing，不运行 commit hooks，也不自动签名。已有仓库的特殊合并状态、当前文件暂存和锁不会被自动清除。

### 外部程序同时修改文件

检测到磁盘与当前编辑同时变化时，两端内容都保留，暂停直接覆盖。可先导出磁盘副本后保留编辑，或备份编辑后载入磁盘，再决定保存哪一份。复杂字符差异在 Worker 中精确计算；超时会提示手动保存，不用近似值代替计数。

## 当前限制

- 文本编码只支持 UTF-8。已有文件保存时保留 BOM 与换行风格；混合换行在编辑后按首个换行风格统一。只读打开不改字节；普通 Markdown 首次主动保存会写入前述 Mark 元数据。
- 已验证平台为 Windows。macOS 开发接续步骤见 [开发指南](DEVELOPMENT.md)，尚未完成实机验收，也没有验证 macOS / Linux 安装包。
- 输入法组合事件有保护，真实中文输入法候选窗仍需人工验收。真实 GitHub 公私有账号授权及跨设备联网往返也需要使用自己的仓库验收；已有自动同步测试使用本机两份工作副本和裸仓库。
- 尚无跨文件全文搜索、PDF 导出、完整 TeX 编译、AI、Notion 数据库、斜杠菜单或跨页 Mark 引用；Word / Excel / PPT / PDF 编辑未接入。

已执行测试与待验收事项分别记录在 [验证记录](VALIDATION.md) 和 [开发清单](../OopsMD-TODO.md)。
